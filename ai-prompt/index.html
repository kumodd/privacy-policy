AI Prompt to Integrate UOAI Provider

Paste one of these self-contained prompts into your AI coding assistant inside your existing Android app to add 100% offline on-device Gemma 3 / Gemma 4 inference via com.uoai.provider—without bundling model weights.

How to Use

  • Pick Path B (Direct HTTP/SSE) if you want zero AAR dependencies, or are integrating into Java, OkHttp, Ktor, Flutter, or React Native.

### Step 1: Inspect My Existing Project First
Before editing any files, inspect:
1. `app/build.gradle.kts` (or `build.gradle`) for `minSdk` (must be >= 26), Java/Kotlin target (17), existing `kotlinx-coroutines-android`, `kotlinx-serialization-json`, `applicationId`, and `buildTypes.debug.applicationIdSuffix`.
2. `AndroidManifest.xml` for any existing `android:networkSecurityConfig`.
3. `app/libs/sdk-release.aar` (verify it exists; if missing, tell me where to drop it and still wire the code cleanly).
4. My existing architecture (Compose vs. XML Views, ViewModel / DI setup, Activity/Fragment lifecycle).

### Step 2: Gradle & Manifest Configuration (Path A — Kotlin SDK)
1. In `app/build.gradle.kts`, add:
   - `implementation(files("libs/sdk-release.aar"))`
   - `implementation("org.jetbrains.kotlinx:kotlinx-coroutines-android:1.11.0")` (or keep compatible existing version)
   - `implementation("org.jetbrains.kotlinx:kotlinx-serialization-json:1.8.1")` (or keep compatible existing version)
2. Ensure `debug` and `release` have distinct `applicationId` values so switching builds on a device never triggers `certificate_mismatch`:
   ```kotlin
   buildTypes {
       debug {
           applicationIdSuffix = ".debug"
       }
   }
   ```
3. Manifest & ProGuard:
   - `sdk-release.aar` automatically merges `INTERNET`, `<queries><package android:name="com.uoai.provider" /></queries>`, loopback-only `networkSecurityConfig`, and R8 `consumer-rules.pro`.
   - ONLY if my app ALREADY defines `android:networkSecurityConfig`, add `tools:replace="android:networkSecurityConfig"` on `<application>` and add:
     ```xml
     <domain-config cleartextTrafficPermitted="true">
         <domain includeSubdomains="false">127.0.0.1</domain>
         <domain includeSubdomains="false">localhost</domain>
     </domain-config>
     ```
     Never enable global `usesCleartextTraffic="true"`.

### Step 3: Implement Provider Connection, Registration & Streaming
Use `com.uoai.sdk.UniversalAIClient` with default `ClientConfig(model = "auto")` (never hardcode a model ID).

Key SDK symbols to use:
- `val ai = UniversalAIClient(applicationContext)`
- `suspend fun checkConnection(): ConnectionState` returning:
  - `ConnectionState.ProviderNotInstalled` -> show prompt to install `com.uoai.provider`
  - `ConnectionState.NeedsRegistration(registrationIntent)` -> launch via `ActivityResultContracts.StartActivityForResult()` (NEVER add `FLAG_ACTIVITY_NEW_TASK` or OS caller verification fails)
  - `ConnectionState.ProviderNotRunning(launchProviderIntent)` -> show one-tap "Open Provider & Start API" button (`launchProviderIntent?.let(::startActivity)`)
  - `ConnectionState.ModelNotReady(modelState, launchProviderIntent)` -> show one-tap "Open Provider & Load Model" button
  - `ConnectionState.Connected(activeModel, capabilities)` -> ready for inference (respect `capabilities.contextWindowTokens` up to 32,768)
  - `ConnectionState.Error(message)` -> show error + Retry button
- `ai.handleRegistrationResult(resultCode, data)` -> returns `RegistrationResult.Approved` or `RegistrationResult.Denied(code, message)`. On `Approved`, call `checkConnection()` again.
- Re-run `checkConnection()` on `Lifecycle.Event.ON_RESUME` so returning from the Provider app auto-connects immediately.
- For multi-turn chat, use `ai.startChat(systemPrompt = ...)` with `session.sendStream(prompt)` (returns `Flow<String>`).
- For one-shot generation, use `ai.generateStream(...)` or `ai.generate(...)`.
- Provide a **Stop / Cancel** button that cancels the coroutine `Job` (the SDK automatically calls `POST /v1/cancel`).
- Handle exceptions cleanly:
  - `CancellationException` / `RequestCancelledException` -> stop cleanly
  - `NotRegisteredException` -> call `ai.clearCredentials()` and re-run `checkConnection()`
  - `PermissionDeniedException` -> tell user to enable `chat` / `streaming` / `tool_calling` in Provider -> Clients
  - `ProviderNotRunningException` / `ModelNotReadyException` / `UniversalAIException` -> show error notice and re-run `checkConnection()` for one-tap recovery (Provider's foreground service is intentionally non-sticky).

### Step 4: Optional Tool Calling Rules (Only if Needed)
- Tool calling (`tools` or `useProviderTools = true`) requires `stream = false` and `toolCalling` permission in Provider.
- Provider tools available: `calculator`, `device_info`.
- Out of scope for Provider: embeddings (`embeddings = false`), STT/audio, and vision inputs (handle those locally in my app before calling chat completions).

Prompt — Path B: Direct HTTP/SSE Integration (Zero AAR)
Best for OkHttp/Ktor custom stacks, Java apps, Flutter MethodChannel, or React Native native modules
You are integrating **Universal Offline AI Provider (`com.uoai.provider`)** into my existing Android app using **Path B (Direct Loopback HTTP/SSE)** with zero AAR dependency, so my app can run 100% offline on-device Gemma 3 / Gemma 4 LLM inference via `http://127.0.0.1:8765/v1`.

### My Feature Goal
[DESCRIBE WHERE AND HOW YOU WANT OFFLINE AI IN YOUR APP — e.g. "Add an offline AI chat/summarize service using OkHttp with SSE streaming and cancellation."]

### Step 1: Inspect My Existing Project First
Inspect my existing project's Gradle setup, HTTP client (OkHttp / Ktor / HttpURLConnection), `AndroidManifest.xml`, `applicationId` / `debug` suffix, secure storage mechanism, and UI layer (Compose, XML, Flutter MethodChannel, or React Native module).

### Step 2: Android Manifest, Loopback Security & Signing Config
1. In `AndroidManifest.xml`, ensure:
   - `<uses-permission android:name="android.permission.INTERNET" />`
   - `<queries><package android:name="com.uoai.provider" /></queries>` (mandatory on Android 11+ / API 30+)
   - `android:networkSecurityConfig="@xml/network_security_config"` on `<application>`
2. Create or update `res/xml/network_security_config.xml` to allow cleartext ONLY on loopback (never set global `usesCleartextTraffic="true"`):
   ```xml
   <?xml version="1.0" encoding="utf-8"?>
   <network-security-config>
       <domain-config cleartextTrafficPermitted="true">
           <domain includeSubdomains="false">127.0.0.1</domain>
           <domain includeSubdomains="false">localhost</domain>
       </domain-config>
   </network-security-config>
   ```
3. In `app/build.gradle.kts`, add `applicationIdSuffix = ".debug"` under `buildTypes.debug` so debug and release builds never collide on SHA-256 certificate pinning (`certificate_mismatch`).

### Step 3: Registration Intent & Secure Token Storage
1. Check if `com.uoai.provider` is installed via `PackageManager.getPackageInfo("com.uoai.provider", 0)`.
2. Launch registration with `startActivityForResult` / `ActivityResultContracts.StartActivityForResult()`:
   ```kotlin
   val intent = Intent("com.uoai.provider.action.REGISTER").setPackage("com.uoai.provider")
   ```
   **CRITICAL:** Never add `FLAG_ACTIVITY_NEW_TASK` to this Intent, or Android clears the OS caller identity and registration fails with `no_caller`.
3. Handle result:
   - `Activity.RESULT_OK`: read extras `token` (`"uoai_..."`) and `client_id`. Store `token` encrypted using Android Keystore (AES/GCM/NoPadding) or `EncryptedSharedPreferences`.
   - `Activity.RESULT_CANCELED`: read `error_code` (`no_caller`, `identity`, `certificate_mismatch`, `disabled`, `rejected`, `cancelled`) and `error`.

### Step 4: Implement Loopback HTTP/SSE Client (`http://127.0.0.1:8765/v1`)
Configure HTTP timeouts: `connectTimeout = 3s`, `readTimeout = 300s` (generation timeout is `300,000 ms`).
Include header `Authorization: Bearer <token>` on every `/v1/*` call except `/v1/health`.

Implement these endpoints:
1. `GET /v1/health` (unauthenticated):
   - Response: `{ "status": "ok"|"degraded", "model_state": "READY"|..., "model_loaded": true|false, "api_version": "v1", "model_error"?: "..." }`
   - If socket connection is refused, Provider's non-sticky foreground service is stopped -> show a one-tap "Open Provider" recovery button (`packageManager.getLaunchIntentForPackage("com.uoai.provider")`) and re-check on `ON_RESUME`.
2. `GET /v1/capabilities` (authenticated):
   - Read `context_window_tokens` (up to `32768`), `default_max_tokens`, `max_tokens_limit`, `max_request_bytes` (`2097152`), `provider_tools` (`["calculator", "device_info"]`).
   - Keep request payload under `2 MiB` and `prompt_tokens + max_tokens <= context_window_tokens`.
3. `GET /v1/models` (authenticated): optional model inspection.
4. `POST /v1/chat/completions` (authenticated):
   - Body:
     ```json
     {
       "model": "auto",
       "messages": [
         {"role": "system", "content": "..."},
         {"role": "user", "content": "..."}
       ],
       "temperature": 0.7,
       "max_tokens": 2048,
       "stream": true
     }
     ```
   - Always pass `"model": "auto"` so it works across Gemma 3 and all Gemma 4 tiers.
   - Read `X-Request-Id` response header immediately (`chatcmpl-<uuid>`) and keep it for cancellation.
   - For `stream: true` (send header `Accept: text/event-stream`):
     - Read line by line; skip blank lines and lines not starting with `data:`.
     - Strip `data:` prefix and trim. Stop on `[DONE]`.
     - Parse JSON: if `"error"` key exists, abort and surface error; otherwise append `choices[0].delta.content` and handle `finish_reason == "cancelled"`.
   - For `stream: false`: parse `choices[0].message.content` (and `message.tool_calls` if using `tools`).
5. `POST /v1/cancel` (authenticated):
   - Body: `{ "request_id": "<X-Request-Id>" }`
   - Call this whenever the user taps Stop or leaves the screen mid-stream.

### Step 5: Error Code Handling
All non-2xx errors return `{"error":{"message":"...","type":"...","code":"..."}}`:
- `401` (`missing_token` / `invalid_token`): clear stored token and trigger re-registration.
- `403` (`permission_denied`): instruct user to enable `chat`, `streaming`, or `tool_calling` in Provider -> Clients.
- `404` (`model_not_found`): fallback to `"model": "auto"`.
- `409` (`request_cancelled`): clean user abort.
- `413` (`request_too_large`): trim history below 2 MiB.
- `429` (`queue_full`): queue limit hit (16 global / 4 per client) -> brief backoff & retry.
- `503` (`model_not_ready`): show "Open Provider & Load Model" button.
- `504` (`request_timeout`): exceeded 300 s -> suggest shorter prompt / lower `max_tokens`.
